> 假设你已经：会 C 语言，玩过一点 STM32（哪怕只是流水灯），能用 Keil 编译烧录。

## Step 1 · 先让它跑起来（10 分钟）

**为什么**：嵌入式项目最容易掉坑的是"代码看了一堆，结果烧上去黑屏不知道哪不对"。先让效果跑出来，你才有信心继续。

1. 接好板子（**德飞莱超翼M35**），ST-Link / SWD 接上
2. 打开 `Project/Oscilloscope.uvprojx`，按 **F7 编译**（应该 0 error 0 warning，Flash ≈ 37 KB）
3. **F8 下载** 到板子
4. 看屏幕：
   - 顶部状态栏：`500us/d  3.3V  AUTO  /\  RUN  CH1+CH2`
   - 屏幕分两条横轨：上半绿（CH1），下半青（CH2），各占 4×10 网格
   - 右侧 80 像素栏：`Vpp / Max / Min / Avg / Frq / Thi / Tlo / Trg` 八行测量值

## Step 3 · 读懂主循环（最重要的 50 行）

**为什么**：整个程序的"骨架"在 `main.c` 的 `while(1)` 里。看完它你就理解了"采样 → 触发 → 绘制"的全流程。

打开 `User/main.c`，找到 `main()` 函数，重点看这一段：

```c
while (1) {
    /* 1. 扫按键 */
    uint8_t key = button_scan(0);
    if (key) Handle_Key(key);

    /* 2. Stop 状态跳过采样 */
    if (!g_osc.run) { delay_ms(50); continue; }

    /* 3. 启动一次双通道同步采样 */
    ADC_Sample_Start();

    /* 4. 等 DMA 完成（500ms 超时，期间继续扫按键）*/
    Wait_Sample_Done(500);

    /* 5. 找 CH1 触发点 */
    uint16_t offset = ...Osc_FindTrigger(g_adc_buf, ...);

    /* 6. 取屏幕宽度的样本 */
    memcpy(s_disp_buf, g_adc_buf + offset, ...);

    /* 7. 测量 + 绘制 */
    Osc_Measure(s_disp_buf, copy_len);
    Osc_DrawWave(s_disp_buf, copy_len);
    Osc_UpdateInfoBar();
}
```

看懂这 7 步你已经掌握了 80%。剩下的就是每步内部怎么实现。

**应当弄懂**：
- `g_adc_buf[]` 是采样原始数据缓冲区，每个 `uint32_t` 元素 = 低 16 位 CH1 + 高 16 位 CH2
- `g_sample_done` 是个 `volatile uint8_t` 完成标志，DMA 中断里写、主循环读
- 三按键 `KEY0/KEY1/KEY2` 映射到时基/量程/Run-Stop

**可以暂时跳过**：触发的"上升沿/下降沿"语义、`Wait_Sample_Done` 为什么不用 `HAL_GetTick`（→ 想知道原因看 `Doc/调试记录.md` 第 6 节）

## Step 4 · 顺着主循环往下钻 — ADC 采样模块

**为什么**：示波器最核心的能力就是"等时间间隔取样"。这一步是为了搞懂"按下按键切时基，屏幕显示的时间尺度怎么就变了"。

读 `Drivers/Src/adc_sample.c`，按这个顺序：

### 4.1 数据结构
```c
static ADC_HandleTypeDef hadc1, hadc2;   // 两个 ADC
static DMA_HandleTypeDef hdma_adc1;       // ADC1 的 DMA 通道
static TIM_HandleTypeDef htim3;           // 用来周期性触发 ADC 的定时器
volatile uint8_t g_sample_done;
uint32_t g_adc_buf[SAMPLE_BUF_SIZE];      // 240 个 32-bit 字
```

### 4.2 采样链路（核心）

```
       TIM3 (1MHz 计数, ARR 控制周期)
            │ 周期性产生 TRGO (Update 事件)
            ▼
   ┌──── ADC1 (master) ───┐
   │   PA0 → CH1          │
   │   ADC1.DR[15:0]      │
   └──────────────────────┘
            │   DUAL REGSIMULT 同步
            ▼ (硬件同步,无需 ADC2 触发源)
   ┌──── ADC2 (slave) ────┐
   │   PA1 → CH2          │
   │   ADC1.DR[31:16]     │ ← slave 数据塞到 master DR 高位
   └──────────────────────┘
            │ DMA1_Channel1 搬运
            ▼ (每次搬 32 bit 字)
       g_adc_buf[i] = (ADC2 << 16) | ADC1
            │ 240 次 DMA 完成
            ▼
       DMA_TC IRQ → HAL_ADC_ConvCpltCallback
            │ 停 TIM3 + 置位
            ▼
       g_sample_done = 1
```

### 4.3 时基怎么实现

`s_tim_arr[]` 表里每档对应不同 `TIM3.ARR`。`ADC_Sample_SetTimebase()` 改 ARR 就改了触发周期，进而改了"两个相邻样本之间的时间间隔"。

TIM3 计数频率 = 72MHz / (PSC+1) = 72MHz / 72 = **1 MHz**，所以每 tick = 1µs。

采样间隔 = (ARR + 1) µs。例如：
- ARR=1 → 2 µs 一个采样对（这是 F103 ADC 的极限）
- ARR=20 → 21 µs（默认 500µs/div 档）
- ARR=8333 → 8334 µs（最慢 200ms/div）

每屏 240 个采样点，所以每屏时间 = 240 × (ARR+1) µs；每格 24 像素 = 24 × (ARR+1) µs/div。

**应当弄懂**：
- TIM3 → ADC 的"硬件触发"链路（外设之间直接连，不走 CPU 中断）
- DMA 为什么是 "Normal 模式" 不是 "Circular"——一帧采完即停，主循环消费
- 双重模式下 ADC1.DR 是 32 位

**可以暂时跳过**：
- ADC 校准 `HAL_ADCEx_Calibration_Start` 干啥（消除 ADC 内部失调）
- `SET_BIT(hadc2->CR2, ADC_CR2_EXTTRIG)` 这一刀为什么补——这是 **HAL F1 库的 bug 补救**，详见 `Doc/调试记录.md` 第 8、9 节

## Step 5 · 波形与界面 — oscilloscope.c

**为什么**：搞清"原始 ADC 数字 → 屏幕像素"的映射，以及"为什么屏幕不闪烁"。

读 `Drivers/Src/oscilloscope.c`，按这个顺序：

### 5.1 坐标映射

每个 ADC 采样值（0~4095 raw）要映射到屏幕 Y 坐标。本工程**双通道分屏**：
- `adc_to_y_ch1()`：CH1 占上半屏，0V→中线，vscale→屏顶
- `adc_to_y_ch2()`：CH2 占下半屏，0V→屏底，vscale→中线

公式核心：
```c
float ratio = voltage / vscale;        // 0~1
y = base - ratio * (half_h - 1);       // 像素位置
```

### 5.2 增量绘制（避免闪烁）

最容易踩的坑：每帧都 `lcd_fill(整个波形区, BLACK)` + 重画 → 屏幕黑闪。

本工程做法：
1. 缓存上一帧每列的 Y 值 `s_prev_ys1[240]` / `s_prev_ys2[240]`
2. 这一帧先**用黑色擦上一帧的线**，再**用 GREEN/CYAN 画新线**
3. 网格 / 标签 / 按键提示**只在 Init 画一次**，永远不擦
4. 信息栏的数字字段只 `lcd_fill` 那一小条 24×12 像素

代价：擦除路径会"啃掉"经过的网格点（视觉上能容忍）。

### 5.3 测量算法

`Osc_Measure()` 用 `(vmax+vmin)/2` 作为阈值（比 vavg 对非对称占空比更稳），扫一遍数据找前两个上升沿 + 它们之间的下降沿：
- **频率** = 1 / (idx_r2 - idx_r1) / sample_us
- **Thi** = (idx_f1 - idx_r1) × sample_us  ← 高电平脉宽
- **Tlo** = (idx_r2 - idx_f1) × sample_us  ← 低电平脉宽

摆幅 < 24mV 视为直流，三个量都显示 `----`。

**应当弄懂**：
- `OscChannelMeas` 结构里每个字段含义
- 为什么 `Osc_DrawTrigLine` 要传上一次的 y 做增量擦除
- 切档时为什么要调 `Osc_ClearWaveArea()`——量程变了 Y 映射变了，缓存的旧 prev_ys 在新映射下对应错误位置

**可以暂时跳过**：
- `osc_show_float` 手写浮点转 ASCII 的实现（就是为了不引入 stdio）
- `osc_show_freq` / `osc_show_pulse` 的 4 字符自适应单位转换

## 一些哲学性的提醒

1. **不要追求一次看懂所有代码**。看不懂的标记下来，先把"主干"看通，等遇到改动需求再回头钻细节。
2. **改之前先理解为什么**。比如"DMA 用 Normal 模式不用 Circular"是因为采一屏就停下让主循环消费——理解到这层再改才不会改坏。
3. **善用 `git log` 和 `Doc/调试记录.md`**。本工程几乎每个 commit 都有为什么这样改的说明，比单看代码注释信息量大得多。
4. **物理极限是天花板**。F103 ADC ~1.17µs/转换决定了"1µs 级死区"这个数量级看不清——这不是软件能优化的事，要么换芯片，要么放弃这个观察目标。
